# LLM Inference Performance Lab

A compact C++17 demonstration of the systems-level performance decisions behind an LLM inference service.

This repository does **not** implement a neural network or claim real GPU benchmark results. Instead, it provides a reproducible synthetic workload for studying several important inference-serving tradeoffs:

**Requests -> Dynamic Batching -> KV Cache Budget -> Prefill/Decode Cost Model -> Latency & Throughput Metrics**

## What this demonstrates

- C++17 inference-serving components
- Dynamic batching by request count and token budget
- Simplified KV-cache capacity tracking
- Prefill vs. decode cost modeling
- TTFT (time to first token)
- p50 / p95 latency
- Tokens-per-second throughput
- Deterministic synthetic workloads
- Automated scheduler and cache tests
- CMake-based build

## Why this matters

Small inference platforms often need to balance competing goals:

- larger batches can improve throughput but increase waiting time;
- long prompts increase prefill cost;
- decode length affects end-to-end latency;
- KV-cache pressure limits concurrency;
- optimizing only GPU utilization can hurt user-visible latency.

This project makes those tradeoffs visible without requiring a specific model, GPU, CUDA version, or serving framework.

## Build

```bash
cmake -S . -B build
cmake --build build
ctest --test-dir build --output-on-failure
./build/inference_benchmark
```

## Example experiment

The benchmark compares several maximum batch sizes over the same deterministic workload. The output reports:

```text
batch=<N> p50_ms=<...> p95_ms=<...> avg_ttft_ms=<...> tok/s=<...>
```

The numbers are generated by the synthetic cost model and should **not** be presented as measurements from real hardware.

## Extension points

The synthetic model can later be replaced or extended with:

- CUDA event timing
- NVML telemetry
- real model-server request traces
- continuous batching
- paged KV-cache allocation
- admission control
- request prioritization
- TensorRT-LLM, vLLM, llama.cpp, or custom runtime adapters

## Engineering intent

The repository is designed as a small public engineering sample showing how an inference optimization problem can be decomposed into measurable scheduling, memory, latency, and throughput components without exposing proprietary client code.
